# 六维任务自检 · 试用版

[打开在线自检](https://privacy.iamtaoxin.com/ai-engineering-interview-handbook/) · [同规则手工版](manual.md) · [完整设计](../docs/assessment-design.md)

在线地址沿用账号现有 GitHub Pages 域名 `privacy.iamtaoxin.com` 的项目子路径。

先做一个领域，留下本次实际记录，再决定下一步学什么。页面提供六个领域、十二个原创任务，每个领域含情境判断与实践；情境有 A/B 两个改变约束的变式。实践记录可引用自己的项目，也可从仓库练习开始。

这是**自行记录、未独立核验的学习自检**。尚未开展真实用户试评、难度校准或评分者一致性研究；不表示覆盖整个领域，不用于能力认证、招聘排名或自动通过 M 阶段。原创任务不增加 102 道来源面经题的计数。

## 一次自检怎么做

1. 选岗位，核对 A1/A2 编程与应用交付基础；缺测先诊断，未通过先补 M0。
2. 选一个领域与未看解答的变式，读给定条件和必要产物，独立填写情境答案。
3. 记录实践和改变约束后的实际结果。没有运行可明确填“本轮未运行”，不需要伪造记录才能结束。
4. 提交完整尝试后查看反馈。草稿不替换上次结果，完成记录不能直接编辑；新尝试保留历史。
5. 看一个主要补课建议，沿具体判据进入 Q/G/L/M，完成产物后再做未暴露的可比变式。

页面不会执行或上传代码，也不会读取证据链接。可计算观测按题定规则比较；开放解释由本人逐项判断并填写理由，格式完整不代表系统已核验真实性。

## 六边形表示什么

| 状态/档位 | 含义 |
| --- | --- |
| 未测 | 没有当前规则下的完整有效自检；不补成 0 |
| 0 | 情境基础必要条件未全部满足 |
| 1 | 基础条件满足，实践条件仍有缺口或尚未运行 |
| 2 | 基础与实践必要条件满足，有具体运行与解释记录，且没有关键断言失败（含改变约束后的实践） |
| 3 | 二档成立，改变约束后的实践、原用例回归和取舍条件也满足 |

六轴顺序与刻度固定，不计算总分、平均分或面积。部分领域未测时仅绘制已有点；六轴完整才连线，文字明细始终与图等价。

最新完整有效尝试替换旧记录，**允许从 3 降至 0**。辅助或答案暴露后的尝试保留为练习，不更新当前图。换岗位只影响建议，不改档位。不同定义版本不混入同一张当前图。

首次完整提交后才展示反馈：实践与改变约束后的实践全部未运行时，只暴露当前情境变式；只要记录了实际尝试并展示共享实践解析，就保守地将本维度 A/B 都记为暴露。未运行项不展示解答。换一个尝试 ID 不能清除曝光；A/B 均暴露后只能继续练习，更多未暴露变式留待后续扩展。因此首版可独立复测基础 A→B；完成高档实践并查看解析后，没有额外的独立复测题组。已经通过源码、手工版或外部提示看过解法，也应如实声明辅助。静态开源工具不能阻止清空本地数据或虚假填报。

已完成练习中出现的关键失败仍优先生成修复建议，但不改雷达；相同判据在后续完整记录中明确通过才能解除该提醒，填“未运行”或另开草稿不能清除。

## 保存和备份

记录保存在当前浏览器；清理站点数据、换浏览器或换设备不会自动同步。可导出完整 JSON 备份并在同版本页面导入；导入不接受文件中声明的分数覆盖公开规则，也不能借旧备份抹除已有答案暴露。导入失败保留原有记录。

备份可能包含自己的项目描述、证据定位和原始摘录，请保存在个人目录，勿提交到公共仓库。页面不自动访问填写的链接，不发送答卷，不加载第三方字体或分析脚本。托管平台可能处理访问日志；这不是整个访问过程“零数据收集”的承诺。

浏览器禁止或无法写入存储时，页面提示临时模式；可以继续当次作答并导出，不能把未保存的记录说成已持久化。完整同伴复核、跨设备同步和真实用户试评尚未提供。

## 本地运行与维护

在仓库根目录，Python 3.10+ 即可生成页面定义与手工版：

```sh
python3 scripts/build.py
python3 scripts/validate.py
python3 -m http.server 8765 --bind 127.0.0.1 --directory assessment
```

打开 `http://127.0.0.1:8765/`。通过 HTTP 访问以加载同源模块与 JSON，不直接双击 HTML 文件。无需模型密钥、账号或第三方包。

修改规则后运行内容检查和 Node.js 22 的标准库测试：

```sh
python3 scripts/build.py --check
node --test tests/assessment.test.mjs
```

`data/assessment.json` 是公开定义源；`assessment/definition.json` 与手工版由构建生成。定义快照附内容 SHA-256，尝试保留规则版本与哈希。个人记录不进入构建。

`scripts/package_assessment.py` 只打包五个白名单公共资源到一个新目录。CI 先通过内容与行为测试，再部署 GitHub Pages；不上传整个仓库、临时数据库或个人记录。发布方式依据 [GitHub Pages 官方工作流文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)，存储故障处理参考 [MDN Web Storage](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API/Using_the_Web_Storage_API)。
