# L02 · 流式重放、任务隔离与取消

这是 [L02 故障练习](../../learning/labs/stream-replay-and-cancellation.md) 的可运行参考示例，使用 Python 标准库、两个独立 SQLite 文件和本地客户端/服务桩。测试会实际写入事件账本、重建页面状态、终止子进程、并发竞争终态并保存观测；不连接真实网络、浏览器 EventSource、LLM 或外部工具。

从仓库根目录运行：

```sh
python3 examples/l02_streaming/run.py
python3 examples/l02_streaming/run.py --output-dir .lab-output/l02-first
```

Python 3.10+，无需安装依赖。`--output-dir` 只创建新目录，拒绝覆盖；再次运行请选择新名字。任何失败、错误、跳过或运行期间源码变化都会返回非零。普通 `unittest` 入口也可使用：

```sh
python3 -m unittest discover -s examples/l02_streaming -p test_streaming.py -v
```

本目录附有一次实际执行的 [报告](verification/report.md) 和 [完整 JSON 证据](verification/report.json)。它们绑定报告内三个源码文件的 SHA-256；不是未来运行的保证，也不是学习者能力评分。重新运行产生的个人报告建议放入已忽略的 `.lab-output/`。

## 协议与持久化

`streaming.py` 中的 `ServiceStore` 保存服务事件账本、当前文本与终态；`ClientStore` 保存每个任务已应用的序号、文本、终态和去重记录。`Session` 只保留当前任务与连接状态。事件字段是 `run_id / seq / type / payload`，序号、保留窗口、快照和取消确认都是本示例定义的应用协议。

| 状态 | 保存位置 | 恢复方式 |
| --- | --- | --- |
| 连接开关、当前选择的任务 | `Session` 内存 | 重建后显式选择任务，再重连；关闭连接不改变任务终态 |
| 每任务游标、文字、终态、完成应用次数 | 客户端 SQLite | 同一事务写入；不能只保存游标而丢掉对应文字 |
| 原始事件、最新文本、终态、保留边界 | 服务 SQLite | 同事务提交；从游标重放，过期时读取同一事务的一致快照 |
| 已启动工具的本地副作用 | 服务 SQLite `tool_effects` | 账本永久保留；取消不删除既有副作用 |

- 正常流严格遵循 A：`1 start → 2 北 → 3 京 → 4 tool-progress → 5 晴 → 6 completed`。重放 2、3 不重复文字；另一个不同 seq 的“哈”仍保留。已经接收过的同一事件标识出现不同内容会报协议错误。
- 新事件必须是 `cursor + 1`。乱序事件与缺口先记录、拒绝前移，不做推测渲染；显式 `recover()` 再拉连续事件。返回的 `through_seq` 也必须到达，才能确认这次重放完整。完整前缀可持久化，下次从该前缀继续；示例不做无限自动重试。
- 服务删除 `<= minimum_cursor` 的事件。游标等于该边界仍可重放后缀；小于边界则返回 `cursor_expired` 与同一读取事务内的快照。快照替换文字与游标，不把完整文字再追加一次。过旧或其他任务快照不能覆盖当前展示。
- 切到 B 后，A 的迟到事件/快照被拒绝，不改 B 的任务记录；切回 A 时从 A 自己的持久化游标恢复。服务认证与租户隔离不在这个练习里，任务标识隔离不等于授权。

## 取消的生效边界

`finish()` 在 `BEGIN IMMEDIATE` 事务内只允许 `running → completed` 或 `running → cancelled` 一次。两种终态不能互相覆盖。后来的取消响应返回服务实际已经提交的终态，而不是把请求里的 `cancelled` 当成结果。

工具启动前的测试屏障位于事务外。释放后，工具在**同一个事务**里检查任务仍为 running、写入本地副作用并发出进度事件。因此取消先提交时，未开始的工具次数为 0；已经写入的工具记录不会因为取消或连接关闭消失。客户端取消请求、服务终态提交和客户端收到确认是三个不同时间点；未收到权威事件前仍显示原任务状态及取消待确认标记。

这个原子边界仅覆盖同一 SQLite 内的合成工具副作用。真实远程工具不可能被这里的 SQLite 事务自动包住，需要结合幂等键、结果查询与恢复协议，例如 [L01](../l01_recovery/README.md)。本示例不承诺取消已开始的远程动作，更不伪造回滚。

## 技术依据与限制

SQLite 官方文档说明同一时刻仅一个写事务，`BEGIN IMMEDIATE` 在事务开始时申请写入；读取事务保持其一致视图。这里据此把序号、文字与终态的修改合并提交。[SQLite transactions](https://www.sqlite.org/lang_transaction.html)

浏览器 SSE 的事件 `id` 和断线重连是传输机制，持久化文字、应用快照和业务取消仍需应用层设计。本实现没有模拟 HTTP、TCP 分片、浏览器后台暂停、代理缓冲或浏览器重试策略；真实项目需要补这些端到端测试。[MDN：Using server-sent events](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)

此处快照是可信本地服务返回值，不验证签名或恶意服务端。记录增长与 SQLite 锁等待也未做生产容量治理；5 秒锁超时会作为异常暴露，不会被当成成功。范围是流式恢复与取消的本地语义，不是生产分布式一致性或性能验收。
