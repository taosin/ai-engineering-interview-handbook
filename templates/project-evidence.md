# 项目复盘记录模板

**内容类型：原创练习模板**。复制到自己的笔记填写；保留“未知”和“待验证”，不要把示例规模、推算结果或 AI 的口头确认写成实测数据。分享时使用模拟数据或脱敏记录。

## 先留下未经修饰的事实

| 字段 | 记录 |
| --- | --- |
| 对应题目 / 指南 / 练习 | Q___ / G___ / L___ |
| 本次业务目标 | 谁需要完成什么任务，完成后有什么可观察变化？ |
| 我的职责 | 亲自设计、实现、检查的部分，以及他人或工具完成的部分 |
| 输入与约束 | 数据版本、权限范围、时间或资源上限；未知条件单列 |
| 原方案 | 关键决策、为何采用、暂时接受的限制 |
| 失败现象 | 能重现的输入、时间顺序、实际结果与预期差异 |
| 修改内容 | 改了什么；哪些其他条件保持相同？ |
| 尚存问题 | 已知限制、未覆盖场景、需要进一步验证的判断 |

## 用证据支持每个结论

每个结论至少填写一行。没有证据时明确标记“假设”；数据不能比较时说明原因。

| 结论或假设 | 前后比较条件 | 证据位置 | 实测结果 | 状态与限制 |
| --- | --- | --- | --- | --- |
| 待填写 | 输入、配置、版本、运行次数 | 日志 / 测试输出 / 评审记录 | 原值、新值、单位、分母或样本量 | 已观察 / 待验证 / 已否定 |

计时应说明起止点；比例应写清分母；成本应注明模型和计费依据；多次执行应保留波动。无法测量就说明无法测量。

## 故障时间线

| 顺序 | 服务端或外部系统发生了什么 | 客户端看到什么 | 此时允许怎样恢复 |
| --- | --- | --- | --- |
| 1 | 待填写 | 待填写 | 待填写 |
| 2 | 待填写 | 待填写 | 待填写 |
| 3 | 待填写 | 待填写 | 待填写 |

对于写操作，标出真正发生副作用的步骤；对于读取，标出认证与授权在哪里执行。区分“请求已发出”“对方已执行”“结果已记录”。

## 整理成面试表达

1. 用一句话交代业务目标、自己的职责和最关键的约束。
2. 解释一个实际决策及其代价，指出被比较过的方案和比较依据。
3. 讲一个可复现的失败过程，再说明修改如何影响这个过程。
4. 展示证据，并主动交代仍未验证的部分；不要把团队结果全部归为个人贡献。

最后请同伴从记录中挑一个反例追问；把答不出的部分转成下一次练习，而不是补写不存在的经历。
